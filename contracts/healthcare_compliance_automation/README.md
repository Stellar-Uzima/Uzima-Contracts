Healthcare Compliance Automation Contract

Stores the regulatory frameworks an operator supports, the policy controls each
framework requires, the assessed status of each control, and the resulting
compliance report.

## Functions

Pre-existing (signatures unchanged, because `npm run abi:check` fails on
breaking changes):

- `initialize(admin: Address, frameworks: Vec<String>)`
- `add_framework(admin: Address, framework: String)`
- `get_supported_frameworks() -> FrameworkList`

Added:

- `add_control(admin, framework, control: PolicyControl) -> Result<(), Error>`
- `get_controls(framework: String) -> Result<ControlList, Error>`
- `record_control_status(admin, framework, control_id, satisfied, evidence: BytesN<32>) -> Result<(), Error>`
- `evaluate_framework(admin, framework: String) -> Result<ComplianceReport, Error>`
- `get_last_report(framework: String) -> Result<ComplianceReport, Error>`

## Compliance model

A framework's checklist is a list of `PolicyControl`s, each with a
`control_id`, a `title`, and a `mandatory` flag. `record_control_status` attaches
an assessment and a hash of the supporting evidence document to a control, so
document contents stay off chain. `evaluate_framework` walks the checklist and
produces a `ComplianceReport`:

- `satisfied` / `violated` / `unassessed` count recorded passes, recorded
  failures, and controls with no assessment. An unassessed control is distinct
  from a recorded failure — `ControlResult::assessed` tells them apart.
- `mandatory_violations` counts mandatory controls that are not satisfied,
  **including those never assessed**.
- `compliant` is `mandatory_violations == 0`, so a partially assessed checklist
  cannot report as compliant. Advisory controls are reported but do not decide
  the outcome.

Reports are persisted per framework and readable with `get_last_report`.

## Authorization

All administrative entrypoints require the stored admin. `add_control`,
`record_control_status` and `evaluate_framework` return `Error::NotAdmin`;
`add_framework` and `initialize` predate the error type and return `()`, so they
panic instead.

Bounds: at most 32 supported frameworks (the list lives in instance storage and
is rewritten on each add) and 64 controls per framework.

## Events

Emitted with `hca` as the first topic. See the `healthcare_compliance_automation`
section of `docs/EVENTS.md`, which is generated by
`npm run events:generate`.

| Topics | Meaning |
|---|---|
| `hca` · `init` | contract initialized |
| `hca` · `fw_add` | framework added |
| `hca` · `ctl_add` | control declared |
| `hca` · `ctl_rec` | control status recorded |
| `hca` · `eval` | framework evaluated |

## Testing

```
cargo test -p healthcare_compliance_automation
```

Build the contract with `cargo build --target wasm32-unknown-unknown`, or deploy
to a local Soroban network with the Soroban CLI.

Real-time monitoring, evidence collection and report generation remain
off-chain; this contract holds the framework definitions, the assessments and
the report, and automation tooling calls into it.
